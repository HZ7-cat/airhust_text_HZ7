## 修改补充
### 第一阶段
首先下载镜像环境，安装新的虚拟机，然后克隆github仓库，进入第一关工作环境，进行`catkin_make`,发现报错
```
geometry_msgs has been found via find_package()
but not listed as a build dependency in the package.xml
```
这是说明要在`package.xml`中加上依赖，于是进入`package.xml`，仿照其他依赖加上
```
<build_depend>geometry_msgs</build_depend>
<exec_depend>geometry_msgs</exec_depend>
```
接着`catkin_make`，发现 `std_msgs`也少依赖，加上。
接着`catkin_make`，发现`drone_backend/DroneState.h`报错，是没有正确加载，进行
`source ./install/setup.zsh`后`catkin_make`成功
寻找 `flight_node`
使用
`ls devel/lib/drone_bringup`
只找到
`example_listeners`
检查源码发现没问题，那么是`CMakeLists.txt`问题，
仿照`example_listeners`，加上
```
add_executable(flight_node src/flight_node.cpp)
target_link_libraries(flight_node ${catkin_LIBRARIES})
```
再`catkin_make`
最后
`./run_sim.sh`
`roslaunch drone_bringup mission.launch`，成功启动
### 第二阶段
启动后发现时间戳为0,失效
于是查看`flight_node.cpp`，并借助工具读懂意思
按照提示和README修改，
1。将`ros::Rate rate(1.0)`表示每秒循环一次，而任务要求维持 500 ms 心跳，改为`ros::Rate rate(10.0)`，
改变时间戳，`ros::Time()`改为 `ros::Time::now()`
话题有问题，`nh.subscribe("/drone", 10, obstacle_cb)`改为`nh.subscribe("/drone/sensor/obstacle_distance", 10, obstacle_cb)`
填写的都是`setpoint`,所以`g_setpoint_pub.publish(fakepoint)`改为`g_setpoint_pub.publish(setpoint)`
要求飞到 1.5 m，则改为`setpoint.pose.position.z = 0.0`
障碍距离 < 0.5 m 之后降落，则改为`distance < 0.5`，再`roslaunch drone_bringup mission.launch`，成功按题目要求
总：学习如何看报错，大概读懂源码，ros文件层级概念，ROS 包的依赖,CMakeLists.txt package.xml的作用
